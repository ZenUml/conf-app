# 客户证据共享规则

由三个客户相关 skill 共用。本目录存放共享数据和参考规则，不是另一个 skill 或运行时。

## 产品与身份范围

读取 `products.json`。客户筛查覆盖其中全部五个产品。`new-customers` 的 `all` 和标准本地 Marketplace 同步覆盖四个 conf-app 产品；Marketplace 在线查询的 `all` 是整个供应商范围，可能包含更多产品。Mini Sites 必须使用登记的 Marketplace key 和自身的遥测数据单独查询，不能悄悄遗漏，也不能用 conf-app 使用数据代替。`forge-installs all` 会报告四个已登记的 Forge ID；Mini Sites 在其 ID 核实前标为不支持。不同工具的 `all` 选项不能视为同一范围。

使用已核实的 cloudId／域名映射及产品身份关联站点事实。按源记录标识去重交易，按“站点＋产品”汇总，不能只按站点汇总。一家公司可能有多个站点；同一站点可以同时安装 Full 和 Lite。先分开统计各版本的使用，合并独立账号数时必须跨版本去重。

“技术联系人”只是来源系统中的标签，不证明对方是站点管理员、预算负责人或仍在该公司任职。姓名、邮箱、职责、职责证据引用、来源日期和渠道应分别保留。核实公司国家和联系人的时区；许可国家与公司所在地冲突时，应记为未知或存在分歧，不能当作时区已确定。

## 每条信号需要携带的信息

`site`、`product`、`kind`、`facts`、`source`、`source_ref`、`occurred_at`（或有明确边界的观察区间）、`queried_at`、`window`、`timezone`、`read_status`、`coverage`、`unknowns`。读取状态为 `ok`、`empty`、`failed`、`unavailable`、`not_queried` 之一。只有在指定范围内成功查询后，才可使用 `empty`。仅有当前状态的记录，不得编造状态变化日期。保留原始来源 ID 以便去重；真实数据留在私有目录。

事实、推断和建议动作必须可以区分。查询 skill 输出事实和信息缺口，不赋予新的执行权限。缓存来源必须带快照时间；今天读取昨天的快照，不会使其变成今天的数据。涉及账单或联系客户的判断，应检查相关的近期原始记录；不要重复刷新无变化且与当前判断无关的来源。

## 信号、来源与可推导结论

| 信号 | 主要证据 | 可以确认 | 单独不能确认 |
|---|---|---|---|
| 新许可起始 | Marketplace 许可、订阅身份、已知历史 | 新许可周期候选 | 首次安装、首次获取这家公司或付款 |
| 安装新增／移除 | 相同产品及范围下的完整 Forge 快照 | 两次快照之间观察到的安装存在状态变化 | 精确卸载时间或原因；查询失败或不完整不等于不存在 |
| 取消／退订／不活跃 | Marketplace 原始状态、历史或反馈 | 已记录状态；有日期证据时可确认变化 | 已卸载、立即失去访问权限，或没有购买意愿 |
| 试用／维护截止 | Marketplace 许可及订阅 | 具体日期和许可类型 | 自动扣款成功／失败，或需要催促客户 |
| 手动空间／用户授权截止 | 带范围的远程 KV key 及值 | 该授权的范围、状态和到期日 | Full 订阅续费、已收款，或所有编辑均受阻 |
| 购买／续费 | 匹配站点、产品和订阅的有效非零 Marketplace 订单，且商业许可已生效 | 商业购买已成立，包括状态为 Open 的订单 | 已确认付款、供应商到账，或重叠发票代表两次独立购买 |
| 付款／退款 | 明确的 Marketplace 付款／退款状态；在账单来源核实的 Stripe／付款引用 | 来源报告的结算状态及有证据的覆盖期 | 供应商银行到账、从累计金额推出当前覆盖期，或 Open 表示客户尚未购买；授权的 `isPaid` 也可能表示赠送访问 |
| 客户意见 | Marketplace 原文、CSAT 提交、D1 报告、邮件／工单 | 客户明确表达的请求、原因或体验 | 未发言用户的意见，或行为因果关系 |
| 活跃使用 | Mixpanel 宏查看／新建／保存事件 | 窗口内观察到的操作和已知账号活跃情况 | 宏存量、安装席位、付费意愿，或统计覆盖范围之外没有使用 |
| 空间存量 | 带时间戳的当前 Confluence／metrics 存量 | 上报的各空间当前宏数量及其覆盖范围 | 从累计新建次数或仅被查看的实例数推出存量 |

## 分析与数据结构注意事项

- 区分**商业结果**、**许可／访问权限**、**来源报告的结算状态**和**供应商到账**。正数 `vendorAmount` 只确认存在一笔已记录金额，不确认付款。保留原始 `paymentStatus`；明确的 Paid／Fully paid 是来源报告的付款证据，Open／缺失／未知应保持“未确认”，不能写成“未付款”。Open 不能推翻已经成立的购买。Marketplace 已记录状态不稳定问题（[MP-577](https://jira.atlassian.com/browse/MP-577)）；这意味着应保留带日期的冲突证据，不代表某个具体客户一定受此问题影响。
- 使用站点／cloudId＋产品＋可获得的 entitlement 匹配交易。结果保留交易 ID、明细 ID、销售类型／日期、金额、维护区间和状态。按重复来源明细去重，不按相同金额去重。不同发票覆盖同一订阅、期间和金额时，标记可能存在替换或重叠，分别保留发票，不把合计当作已独立确认的收款。退款、作废、取消记录不作为购买证据；仅有 $0／免费记录不能确认付费转化。未来覆盖期和历史付款不能表述为当前已付费覆盖期。
- `macro_viewed` 表示产品使用；D1 `page_viewed` 表示 Confluence 页面活动。新建和更新是不同操作；两者都是保存，但都不是当前宏存量。
- 人数统计排除缺失账号和已知占位账号 ID：`unknown_user_account_id`、`unknown`、`anonymous`、`null`、`undefined`。不能把任意不透明格式的真实账号 ID 一概排除。能获得匿名事件量时，单独报告。
- 说明排名分母、入选客户集合、时间窗口、产品范围和并列处理方式。`client-health` 使用活跃 Lite 站点及相对分数；新建使用覆盖程度／席位档位不等于全员采用率。上期为零可能放大增长幅度。把 Lite 分数视为升级机会前，重新检查 Full 许可。
- 当前 Forge 同步代码已包含 cloudId／站点映射和 Graph 的 `macro_viewed`；旧文档称这些从不存在，只代表历史情况。关联 D1 前核实生产部署、空值和日期覆盖。D1 同步可能失败，因此不是完整图表台账，也不保证提供可靠的存量边界。
- D1 `FeedbackReport` 的能力依赖部署情况；检查结构和访问能力，并报告覆盖缺口。Mixpanel 工作流事件不一定带反馈报告引用。
- 远程 KV 读取失败或值格式错误时，必须保持未知。成功读取空列表是另一回事。key 格式为 `license:<cloudId>:<spaceKey>[:<userAccountId>]`；账号 ID 本身可能包含冒号。

## 访问与复用

使用现有 Marketplace 导出／快照、Forge 安装 CLI、Mixpanel 查询运行时、已配置的只读 D1 路径以及 Gmail／JSM 连接器或浏览器会话。不要另外创建凭据存储，也不要假设客户数据是公开的。本地 CRM 提供分类语义和已知覆盖限制；模拟 UI 动作不能证明生产系统发生了变化。

某个来源不可用时，不得声称所有来源都已检查。报告已获得的有用结论，并明确缺失哪个来源，不要把访问失败当作空结果。

## 结构化缓存与刷新策略

再次导出前，先复用已有来源缓存：Marketplace SQLite、Forge JSON 快照和私有查询结果。当前使用的清单记录在 `private/operations/customer-evidence-cache.json`。私有运行清单应包含来源／查询 key、站点／产品范围、请求窗口和时区、`queried_at`、来源快照时间、读取状态、数据文件路径、刷新策略及最近一次刷新失败。复用数据必须保留原时间戳。

- **站点／产品身份：**复用已核实映射；发现冲突标识、站点迁移或产品登记变更时使缓存失效。不要反复查询没有变化的 ID。
- **联系人职责／公司背景：**复用证据和来源日期；出现新转介、地址冲突，或职责对当前动作有实质影响时再复核。缓存中的技术联系人不会自动成为已核实管理员。
- **许可／付款：**筛查默认可用24小时内成功获取的快照；如果缓存不足以支持付款、访问、续费结论或动作，先刷新相关订阅。试用截止可以触发数据刷新，不会自动触发联系客户。
- **完整使用窗口：**复用完全相同的查询、窗口、产品和身份定义。近期窗口在视为不再变化前，要考虑延迟入库；不要只为重新生成摘要而重复查询无变化的旧窗口。
- **反馈／消息：**保留原始来源 ID 和正文；来源支持时，查询上次成功检查以来的新增／更新；线程当前状态与旧消息内容分开保存。执行相关沟通动作前，重新读取回复、草稿和定时消息。
- **刷新失败：**单独记录失败尝试，保留上一次成功的数据及时间戳；时效性有影响时标记为过期。不得发布不完整刷新，也不得把缺少完成标记当作成功且为空。

这些默认规则指导已授权的运行，不创建后台刷新任务，也不扩大联系客户的权限。
