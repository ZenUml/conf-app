技能名称：customer-tracker

技能用途：依据已核实证据和决定更新“客户转化管理”客户跟进表，包括机会摘要、跟进记录、仅状态刷新和表格结构编辑。本 skill 维护工作簿；不负责查询客户或作出销售决策。

# 客户转化管理表维护

根据 `customer-followup` 或其他已授权来源提供的已核实事实和决策，维护现有“客户转化管理”电子表格。本 skill 只负责工作簿编辑；不负责来源调查、客户情况解释、销售决策或对外沟通。

字段的规范含义见[customer-followup 记录](../customer-followup/references/records.md)和[customer-data 证据规则](../customer-data/evidence.md)。私有工作簿适配文档 [`private/operations/customer-followup-tracker.md`](../../../private/operations/customer-followup-tracker.md) 负责实际工作簿和工作表 ID、当前表头、列映射、时区及工作簿专属约定。编辑表格前先阅读该文档；不要把其中的私有标识复制到公开 skill 内容中。

## 范围

- **事实刷新：** 更新经核实的机会摘要，并追加有日期的跟进记录。
- **仅状态刷新：** 根据符合规范记录规则的已核实事实，对照更新当前阶段、障碍和已过时的下一步文字；不要自行拟定新的外联计划。
- **结构编辑：** 仅在收到请求时变更表头、列、公式、验证规则或布局。将其视为工作簿范围的改动，并核实引用和结构是否随之更新。

不要发送或安排客户沟通、授予许可证或作出销售决策。当提供的已核实事实符合规范记录规则时，应对照修正阶段、障碍和已过时的下一步文字；更正过时的表格状态不需要新的人工决定。保留用户要求的暂停/观察范围，并将其与购买或付款状态的事实分开处理。若证据冲突或不足，与调用者核实。若缺少必要事实，将具体证据请求交回 `customer-followup`；不要从本 skill 发起完整调查。

## 准备改动

1. 阅读私有适配文档和当前工作簿。按稳定的 `OPP-...` 身份匹配机会，不要只按行号或客户名称匹配。检查 ID 重复、缺失和工作表错误；遇到问题时隔离受影响行，在写入前解决映射。
2. 复用已核实证据及其原始来源时间戳。缺失数据不等于零，也不能证明未付款。来源不完整或不可用时，保留最后一个有日期的事实并标记为过时，或标记为未知；来源不可用时，绝不要填写新的核实日期。
3. 以机会 ID 和当前表头为键，制作最小化补丁，并记录旧值、新值和证据/来源。保存写入前快照。写入前重新读取受影响单元格，检查并处理并发修改；不要覆盖更新的内容。
4. 对跟进记录保留来源 ID、日期，以及观察事实与决策之间的区别。检查已有 `ACT-...` ID 和来源/动作身份，确保重试不会重复追加同一条记录。新增机会时，按经核实的站点 + 产品 + 目标去重，从当前记录/历史记录中分配未使用的稳定 `OPP-...` 和 `ACT-...` ID；只有必要时才扩展原生表格、验证规则和公式范围。不要硬编码下一个 ID，也不要创建重复行。先添加活动记录，再添加指向该记录的摘要链接。

## 字段专属处理

- 全站年化潜力依据提供的已核实产品、许可席位数、定价日期及计算结果记录，采用适配文档约定的口径（当前为累计阶梯月费 × 12）。这是潜在金额估算，不是年度报价、付款或收款。单空间的独立 $299 方案不属于此全站计算。明确标注未知席位和估算；如缺少输入，将请求交回 `customer-followup`，不要自行开展定价调查。
- 当前近7天活跃列应说明提供的连续七个完整自然日、时区、产品范围、查看者、查看次数、新建次数和更新次数。用户要求的其他窗口必须明确标注。使用上游提供的跨版本查看者去重结果；不要在此重新计算或发起新查询。要区分成功完成的产品范围查询且事件数为零，与未执行、不可用或不可比较的查询。Mini Sites 使用独立遥测。
- 将购买证据与付款/结算状态分开记录。不要因为付款状态为 Open 就推断“没有购买”，也不要把未核实金额写成已收收入。

## 写入与恢复

对已知 CLI（例如 `gws`）支持的执行动作，业务读取和写入**必须使用 CLI**。核验是独立例外：即使 CLI 支持相应读取，也可以使用 CLI 或 UI 核验结果。能力不确定时先检查命令帮助／schema。工具未安装、认证失败、凭据过期、OAuth 权限不足和运行错误，都不代表 CLI 缺少该能力。报告具体错误，但不得泄露凭据，并停止受影响的执行动作；不能改用 UI 或 connector/API 绕过问题。UI 仍可核验已经执行的动作，但不得掩盖 CLI 的失败。

执行时，**只有 CLI 确实无法完成的能力才使用 UI**。UI 也允许用于核验，包括已保存的单元格值、格式和实际渲染布局。connector/API 可以用于 CLI 确实不支持的能力，但不能替代 CLI 已支持的动作。准备好的 TSV、命令成功、完成点击／粘贴或本地工作簿编辑，本身都不能证明线上表格已保存。遵循私有适配文档；共享工作簿／会话只安排一个写入者，其他协作者可以准备和核验补丁数据。

优先按单元格编辑。小范围改动不要替换整张工作表。保留公式、数据验证、链接、数字/日期格式、原生表格、条件格式（包括暂停行灰色样式和审查公式）以及冻结窗格。移动或插入列后，按映射后的单元格核对公式引用；绝不要把原始值覆盖到公式列。结构改动后还要检查屏幕上的列宽、换行、日期和下拉选项。

写入后读取受影响的行。批量或结构编辑应对照预期值和未修改的值、公式结果/错误、机会和活动 ID 的唯一性以及相关结构。CLI 快照和 UI 回读都可以提供核验证据；证据覆盖范围必须足以验证本次改动，不能以一个可见单元格证明整批更新。只有 CLI 不具备的能力才允许使用 connector/API 证据。只要快照包含等效的值、公式和元数据，就不必另行导出工作簿。结构布局变更仍须目视检查，可以使用 UI。比较有实际意义的样式属性，不要比较 XLSX 样式 ID。如果写入只完成一部分或状态不确定，重新读取线上状态，仅修复缺失或错误的单元格；绝不要盲目重放补丁或重复追加活动记录。跟进表写入失败，不构成撤销单独发送的邮件、已安排的消息或许可证授权的理由。

报告状态为**已保存并核验**、**部分已保存**或**仅完成准备**，并指出未解决的不匹配或证据缺口。只有在工作簿布局确实发生且已核实变更后，才更新私有适配文档；否则保持不变。
