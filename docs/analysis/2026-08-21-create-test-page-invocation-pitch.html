Invocation design · 21 August 2026

Name the target dimensions; keep the registry behind the CLI

The current --profile app@site interface bundles three independent decisions into one opaque token. That makes the command harder to read, harder to validate, and easy to misapply when multiple apps share a Confluence site.

Recommendation: make --app, --environment, and --site explicit. Keep the registry internal: it resolves app IDs, Forge environment IDs, namespaces, module keys, and content keys, then validates the tuple before the first POST.

Proposed invocation

node .claude/skills/create-test-page/scripts/create-test-page.mjs \
  --app diagramly \
  --environment staging \
  --site diagramly-staging \
  --space SD \
  --macro mermaid:./fixtures/flow.mmd

The same shape works for every variant. The site value is the tenant alias; the app and environment select the Forge identity.

Why this is clearer

Readable intent

A reviewer can see which app is being tested, where it is deployed, and which tenant receives the page.

Correct shared-site behavior

Production sites can host Lite, Full, and Diagramly simultaneously. A site name alone cannot select the macro extension.

Safe configuration

The caller never supplies app IDs or Forge UUIDs. The internal registry owns those values and rejects unsupported app/environment/site combinations.

Parameter contract

ParameterMeaningValidation
--applite, full, diagramly, or asyncapiDetermines app ID, namespace, macro modules, and content keys.
--environmentdevelopment, staging, or productionDetermines the verified Forge environment ID.
--siteNamed Confluence tenant / approved aliasMust be allowed for the selected app and environment.
--spaceConfluence space keyRequired; API failure is reported before any page is left behind where possible.
--macroRepeatable type:file inputAt least one; type and file are checked before the first network write.

Rejected alternatives

--profile diagramly@stg

Rejected as the public interface: it hides the site and conflates environment naming with tenant naming.

Caller-supplied --app-id / --env-id

Rejected: it moves Forge identity knowledge into every invocation and invites guessed UUIDs.

Site-only selection

Rejected: one site can contain multiple app variants, so site-only targeting can create a valid page for the wrong renderer.

Scope and tradeoff

The implementation still uses a declarative registry; the change is only where the abstraction boundary sits. The registry remains the source of truth, while the command expresses user intent in three dimensions. This adds two flags but makes failures actionable and prevents silent cross-variant tests.
