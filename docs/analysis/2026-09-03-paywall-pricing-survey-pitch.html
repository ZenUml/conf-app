+ Pricing survey extension — review draft
Review draft · 3 September 2026

Turn a paywall interruption into priced, actionable evidence.

When a Lite user asks for more editing time, we can collect the pricing context that explains the request and immediately reward a complete response with 15 days of user-scoped editing.

Decision requested: approve the in-app pricing-survey extension path, subject to one clean staging validation after the correct build is served to a non-exempt paywall fixture.

The user problem

Blocked users need a useful next step

“Request extension” previously handed a user directly to support. The highest-intent moment produced little structured pricing evidence and a delayed outcome.

Pricing decisions lack context

A price alone is weak. The flow records role, four willingness-to-pay points, preferred billing unit, and the internal blocker.

Support should not be the only unlock route

A completed survey creates a 15-day license for that user in that space, allowing them to continue editing immediately.

What was built

MomentExperienceSignal / safeguard
Request extensionThe modal swaps to a four-question pricing survey before the support hand-off.Role, Van Westendorp price points, best/worst billing unit, blocker; optional comment.
AnsweringAnswers save as the user types; submission is enabled only for a complete, ordered price battery.Partial responses remain identifiable as incomplete research, rather than silently disappearing.
SubmittingThe user sees an unlocked state, then continues editing without consuming a metered continue attempt.One survey reward per user per space; an existing longer license is never shortened.
SkippingThe existing support route remains available.The request carries the survey response ID so support can connect the hand-off to the attempt.

Why this design

Aligned incentive

The in-app and email paths ask the same questions and offer the same 15-day value. Skipping does not yield a better reward.

Research that can be trusted

The price sequence must be non-decreasing and “best” cannot equal “worst,” preventing unusable responses from entering the submitted corpus.

Privacy-aware measurement

Funnel events record answer categories and numeric prices; optional comment text is excluded from analytics and kept only in the controlled response store.

Tradeoffs and boundaries

The survey deliberately sits before support because users who leave for a service desk seldom return to answer it. That trades a small amount of form friction for structured, comparable pricing data and a self-serve result. The reward is intentionally user-scoped—not space-wide—so one response cannot unlock editing for an entire team.

This does not decide the eventual pricing model. It creates a disciplined source of evidence for that decision and retains the support rail for users who need a longer or team-wide extension.
