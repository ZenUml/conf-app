Source Binding Engine: Stage 3 fingerprint scoring

This stage compares static facts for a parser-confirmed Mermaid Flowchart node candidate and produces a transparent evidence score. A score is not identity confirmation, logical-node continuity, Architecture Token retention, or binding transfer. The following stage is global maximum-weight assignment, which still has to enforce one-to-one and fail-closed rules.

The score is built from revision-local facts: native ID, node kind, normalized label, shape, neighborhood, and container path. Source-diff relocation and statement-context facts are displayed separately because they are evidence at this gate but are not weighted score components. Missing or ambiguous static facts cannot be scored safely and remain unresolved.

Stage boundary

This document covers Mermaid Flowchart nodes only. It exercises the parser, UTF-8 source-diff preparation, exact native-ID candidate assessment, static fingerprint extraction, and Stage 3 scoring. It does not perform global assignment, topology iteration, split/merge or delete/recreate resolution, user confirmation, AI suggestions, logical identity confirmation, Architecture Token retention, Confluence writes, backend indexing, or cloud access.

The duplicate-facts example starts with real fingerprints produced from parsed nodes, then intentionally repeats one fact record to represent ambiguous stored evidence. The decision still comes from the real fail-closed scorer; no outcome is mocked.
