Source Binding Engine: Stage 2 exact native-ID candidate assessment

This stage compares two parser-confirmed revisions of a Mermaid Flowchart and looks for an exact native Mermaid ID with the same element kind. It produces a candidate assessment only: it never confirms logical identity, retains an Architecture Token, or transfers a binding. Those decisions require the later fingerprint and assignment gates.

A native ID is revision-local evidence, not a stable logical identity. Even when an ID is unchanged, a candidate must continue to later gates. A changed label has no exact source-diff relocation for the changed node, and duplicate or absent IDs fail closed rather than being guessed.

Stage boundary

This document covers Mermaid Flowchart nodes only. The parser remains the source authority and source-diff relocation remains a separate evidence stream. Stage 2 does not score fingerprints, perform global assignment, resolve split/merge or delete/recreate, confirm a logical element, retain a token, write Confluence content, call a backend, or create an index.

The duplicate example deliberately supplies the same parser-confirmed node fact twice to the Stage 2 candidate assessor. This makes the one-to-many input explicit while keeping the decision under the real fail-closed native-ID logic.
