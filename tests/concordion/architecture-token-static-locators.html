Architecture Tokens · Source Binding Engine · Phase 1

Static syntax-based locator correctness

A Flowchart node binding starts with a safe address into one source revision. This product specification shows how the address is earned: Mermaid validates the syntax, the owned Flowchart parser identifies node syntax, and the UTF-8 byte span round-trips to the exact source fragment.

What this phase owns

Included

Mermaid Flowchart nodes, declarations, endpoint occurrences, syntax-derived primary locators, and byte-safe source selection.

Evidence only

Native IDs, labels, shapes, container paths, statement context, and neighbouring IDs are static fingerprint facts—not identity decisions.

Explicitly deferred

No revision comparison, migration, reconciliation, token matching, Confluence persistence, UI, backend, D1, or cloud dependency is exercised here.

Exact stage order

  1. Official Mermaid syntax validation. Invalid Mermaid stops the pipeline.
  2. Flowchart source parsing. The owned parser accepts only its explicit node subset.
  3. Canonical elements versus source occurrences. One logical node may have several appearances.
  4. Primary locator plus occurrences. The first syntax occurrence is primary; every occurrence remains available as evidence.
  5. UTF-8 byte-span round trip. A locator selects the exact source bytes, including CJK and emoji.
  6. Static fingerprint facts. Facts explain the observation; this phase does not match identity across revisions.

Product contract

A locator is not a Mermaid ID, label, edge label, style reference, or subgraph title. It is a syntax-derived UTF-8 byte span attached to a canonical Flowchart node. A forged or byte-unaligned span is rejected rather than selecting an arbitrary fragment.

This is intentionally a single-revision specification, so there are no Before/After columns. The examples describe what the Source Binding Engine can safely observe before any future version comparison exists.

Boundary statement

Passing this document proves static locator correctness for the owned Flowchart subset. It does not prove that a node is the same node in a later revision, that a user intended a token binding, or that a token exists outside this source. Those are separate product decisions and are intentionally not part of this first phase.
