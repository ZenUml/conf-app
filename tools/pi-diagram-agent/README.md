# Pi diagram improvement agent

This local prototype has one product entry point: the Pi `/magic` command. It starts a **real model turn**. Pi receives the complete pinned Diagram Rules and exact original Mermaid bytes, creates a diagram-specific native SVG, inspects the original and candidate images, and revises the candidate. It does not call a fixed layout pipeline to choose the design. The earlier deterministic experiment remains in the separate prototype repository history for research, not as a supported conversion fallback.

Load the extension with the Pi 1.0.0 runtime (RPC clients finish a run on `agent_settled`, not `agent_end`):

```sh
pi --extension ./pi-extension.ts
```

Then run `/magic /absolute/path/source.mmd`. The command selects an available **native `openai-codex` vision model** for this task and runs the first draft at medium thinking, switching to high after the first successful inspection (see below), without changing the user's global Pi default. Set `PI_DIAGRAM_CODEX_MODEL` to choose a specific model ID from `pi --list-models openai-codex`. Authenticate through Pi's supported `/login` flow; do not copy or export the Codex desktop credential. If no authenticated native model is available, the command stops before sending the source to another provider.

Continue a candidate in the same `/magic` workflow with `/magic /absolute/source.mmd --resume /absolute/pi-diagram-agent-run --reference /absolute/accepted.svg --feedback /absolute/review.txt`. A resume requires the run's exact source/rules hash manifest and existing candidate; the accepted SVG is shown to the agent as full and viewer-fit **reference images**, never copied as output. If the pinned rules changed since the run began, add `--upgrade-rules` to that resume command. A user adjudication of a declared-versus-rendered group conflict enters **only** through the human-invoked command: add `--adjudication /absolute/adjudication.json` (one record or an array). The file is read once at command start, must be an absolute path whose real path lies **outside** the run directory (a path or symlink into it is refused), and its SHA-256 and parsed records are written to the run's `.job.json` before the model turn. `diagram_inspect` audits with the in-memory copy of that manifest and refuses to run if `.job.json` was rewritten afterwards. An `adjudications.json` in the run directory, or adjudications in an older `.job.json`, are never read, because Pi can write anywhere in its run directory; pass `--adjudication` again on every resume that needs it. Residual risk: Pi also has general shell access, so "outside the run directory" is not "unwritable by the model" — the trust boundary is the operator choosing a file they authored and reviewed, and the recorded SHA-256 lets them confirm afterwards which bytes were used. A rewritten `.job.json` between commands can still change the recorded rules history on the next resume (the pinned rules text itself is fixed by hash in code). The original Mermaid render's SVG is likewise kept in memory after its first render, so rewriting the run-directory copy does not change later audits. This records both rules hashes, sends the **entire new rules text** to Pi, and requires a fresh image inspection; old receipts are not promoted to the new rules revision. Reviewer feedback and source remain private local files. Quoted paths with spaces are accepted.

The command creates a fresh private work directory and gives Pi a fixed `candidate.svg` path. Pi may use its ordinary file and shell tools to author a source-specific script and SVG. After each candidate it calls `diagram_inspect`. That tool renders the exact Mermaid source using a local Mermaid bundle, renders the candidate at 2×, and returns the original full image, candidate full image, four candidate crops, and a 1200×710 contain-fit image as actual image content. It also returns exact source/SVG/media hashes and a narrow independent source/SVG binding audit. Pi must actually inspect the images, compare the original and candidate, state concrete observations about legibility, layout, legend, arrows, alignment and clearance, then repair visible defects and inspect again. Generating PNG files or receiving machine checks alone does not complete visual review. Rendering is evidence, never a quality certificate.

Local browser requirements: set `PI_DIAGRAM_PLAYWRIGHT_MODULE` to an installed Playwright module (or install it in this package), `PI_DIAGRAM_MERMAID_BUNDLE` to a locally installed Mermaid `dist/mermaid.min.js`, and optionally `PI_DIAGRAM_CHROMIUM_EXECUTABLE` to a Chromium executable. The tool blocks external browser requests, bounds inputs and screenshot pixels, and refuses candidate symlinks. No customer source is committed to this package.

`src/agent-audit.mjs` is deliberately independent of the old renderer's `data-box`, `data-points`, source-derived ranks, or palette classes. With neutral node/relation IDs it checks drawn text, directed edges, dashed style, original-render versus candidate group containment, actual connector endpoints, sampled node and heading intrusion, straight-span crossing and 10-unit parallel clearance, visible markers, and final straight arrow shafts. It also checks T2 text fit (every node text bbox inside its rect/capsule outline inset 8 units; a non-rect shape needs a declared `data-label-box`, else **NOT-CHECKABLE**) and B5 label clearance (edge-label text plus background, marked `g[data-edge-label-source][data-edge-label-target]`, disjoint from every node and container outline stroke within a 0.5-unit epsilon and never inside a node box; every labelled source edge needs its own tagged label, else **NOT-CHECKABLE**). For T2, only painted shapes form the outline, a node with no bound text is **NOT-CHECKABLE**, and every corner of a declared `data-label-box` must lie inside the drawn shape, not merely its bounding box (exact for convex shapes). A declared-versus-rendered membership conflict stays **FAIL** unless a hash-bound user adjudication (`{nodeId, declaredGroup, renderedGroup, chosenGroup, authorisedBy, timestamp, sourceHash}`, one record or an array, passed as the `adjudications` option or through `/magic ... --adjudication`) matches the source hash, original render and candidate, which reports **ADJUDICATED** with the record, never PASS; `authorisedBy` is recorded, not authenticated. `routeLowerBend` reconstructs each drawn route's logical bends from its actual path and, for rectangular endpoints only, searches straight and one-bend L candidates (face midpoints, projected alignments, a 4-unit face sweep) that are perpendicular, clear of unrelated nodes/containers/headings/labels, crossing-free, 10-unit parallel-clear and long enough for rule 13; a feasible fewer-bend route, or a same-bend route with anchors nearer the face midpoints, is a **FAIL** with a faces/anchors/segments witness, while non-rectangular endpoints, curved non-fillet paths and unbound labels are listed per relationship as **NOT-CHECKABLE** and uncertain obstacles can block a witness but never support a PASS. These are scoped checks: continuous curve/container/label exclusion, 2-bend alternatives and midpoint search beyond that candidate set, semantic palette meaning, and final optical quality remain separate. Missing tags or Mermaid syntax outside its narrow source parser make the corresponding check **NOT-CHECKABLE**, not a judgment that the drawing is poor; screenshots still reach Pi. A source declaration that conflicts with the original rendered group is explicitly **FAIL**, even if the candidate preserves the visible original by default. The current agent-led flow emits a candidate; it does **not** emit a validated Magic artifact yet.

`routeDetour` compares each drawn route's Manhattan length with the shortest feasible witness (the `routeLowerBend` candidates plus an obstacle-grid Dijkstra over whole straight segments, every winner re-validated by the same evaluator) and **FAIL**s when the route is longer than both 1.15x and +300 units over it (calibrated: the first proposal, 1.5x/+200, missed both known canvas-edge detours); a route within that limit of the plain Manhattan gap between its endpoint shapes passes without a search, and a relationship with no feasible witness is **NOT-CHECKABLE**, never PASS. `routeContainerClearance` is rule 6 and B5 for containers: a straight span running within 8 units of a container border for more than 24 units is a **FAIL** (the crossing point of a border the connector must cross is exempt within 12 units; riding along the inside of the source or target container still counts), and an edge label (tagged, or untagged and uniquely matched to a source label) overlapping or within 4 units of a container border is a **FAIL**. Long runs in gutters of 40 units or less are listed as advisories only, because the pipeline's own gutters are 30-40 units. Both checks are early findings and block the gate.

The auditor also measures six layout and style rules from the drawn SVG (`src/layout-checks.mjs`, computed styles and actual path geometry, never the author's metadata beyond neutral tags): `connectorStrokeWidth` (rule 8: every connector computes to stroke-width 1 unless it carries a `data-emphasis` role whose meaning is written in an SVG palette comment), `filletUniformity` (rule 3: every bend measured from the path's Q/A/C fillet or sharp L-L corner must be r=5; a non-orthogonal curve makes that edge NOT-CHECKABLE), `markerUniformity` (rule 7: `userSpaceOnUse`, identical size and geometry, `refX` at the tip, no `context-stroke`/`context-fill`), `textContrast` (every text fill against the top-most solid painted shape under it, at least 4.5:1; gradient, translucent or absent backgrounds are NOT-CHECKABLE), `labelFontWeight` (T4: node labels and descriptions are 400; direct group headings and `data-role="ordinal"` text may be heavier) and `legendCompleteness` (C5: a legend is optional, so only a drawn legend that contradicts the drawing is checked. No legend: PASS with basis "no legend; legend is optional". A drawn entry that contradicts actual use is a blocking FAIL: a dashed line key while no connector is dashed, a fill swatch no node, container or label uses, or a shape swatch no node is drawn as. Keys missing from a drawn legend (a fill role, shape or line style in use) are a minor, non-blocking finding carried on the PASS). Any FAIL fails the audit and the v2 gate, appears as an early finding at every `diagram_inspect`, and a PASS is passed to the reviewer as measured so it is not re-litigated (a reviewer `legend` finding is downgraded when `legendCompleteness` PASSed with a verified swatch, and a blocking reviewer `legend` finding that only reports a missing legend or missing keys, with no contradiction wording, is downgraded to minor by code). Facts are collected in one browser pass; NOT-CHECKABLE is never promoted to PASS.

`kit/svgkit.py` is an optional stdlib-Python library of drawing primitives (node shapes, label tiers, r=5 fillet paths, one arrow-marker geometry emitted per connector colour, edge-label pills, containers, legend items, palette contrast checks, SVG assembly) that the agent prompt points Pi at, so each generator stops re-writing that boilerplate. It is deliberately not a layout pipeline: the model passes every position, port and route point, and the kit chooses none of them (see `kit/README.md`). Run `npm test` for source, audit and kit tests (it also runs the Python kit tests). The Chromium-dependent synthetic tests require the browser environment above; without it those checks are reported as skipped.

This package emits candidates and visual evidence. It does not yet emit a certified Magic artifact. Two private historical candidates remain **UNCERTIFIED**; their diagrams, references, screenshots, and evidence records are deliberately excluded from this public package. Neither full quality certification nor a speedup is claimed.

See [MIGRATION.md](MIGRATION.md) for source provenance and the supported file boundary.

## Speed defaults (on by default)

Based on a 15-vs-15 benchmark (time to first inspection 147 s to 48 s, total elapsed -25%, no visible quality loss):

- First draft runs at `medium` thinking, then `/magic` switches to `high` right after the first successful `diagram_inspect`. The inspection result JSON carries `thinking: {firstDraft, revisions, switchedAfterMs, current}`. Opt out with `PI_DIAGRAM_FIRST_DRAFT_THINKING=high` (no switch, high throughout); any other level (e.g. `low`) sets that first-draft level.
- The prompt asks for a direct first candidate (no separate planning message, brief reasoning until the first inspection). Opt out with `PI_DIAGRAM_DIRECT_DRAFT=0`.
## Speed experiments (opt-in, both default off)

- `PI_DIAGRAM_SPEC_MODE=1` registers `diagram_render_spec` and adds a short schema paragraph to the prompt. The model may write `layout.json` (canvas, palette roles with meanings, groups, nodes, edges with explicit orthogonal `points`, legend) instead of a generator script; `src/spec-render.mjs` draws it exactly into `candidate.svg` (uniform r=5 fillets, per-colour markers, label pills, auditor tagging) and returns text findings. It never moves, reroutes or repairs anything and never fails on a rule violation; only malformed JSON or schema errors are rejected, with a path and message. The model still decides every coordinate.
- `PI_DIAGRAM_SOURCE_FACTS=1` appends parser facts (nodes, edges, groups, declared vs rendered group) and each node's position in the original Mermaid render, labelled reference only. The original is rendered before the first model turn and reused by `diagram_inspect` (hash-bound).

## v2 loop: independent reviewer and deterministic gate (default)

Status: implemented MVP, K=1 author. Full spec: [docs/design-v2.md](docs/design-v2.md). `PI_DIAGRAM_V2=0` restores the single-session loop (no `diagram_submit`, unchanged prompt, no `run.json`) so benchmarks stay comparable.

The author no longer decides it is finished. It calls `diagram_submit` and the orchestrator (extension code):

1. reads the final `candidate.svg` bytes and renders them itself (never trusting the author's last `diagram_inspect`);
2. runs the auditor plus early mechanical checks (forbidden constructs `context-stroke`/`context-fill`/`script`/`foreignObject`/`href`/`on*`, missing node, relation and group bindings, and two measured geometry checks: an edge label more than 25 units from its own route, and a route closer than 12 units to the border of an unrelated node or container). The same early checks are returned in every `diagram_inspect` result;
3. on any failure returns structured findings (`id, source, severity, rule, elements, region, evidence {measured, threshold}, suggestion`) and the author continues in the same session;
4. if the audit is clean, runs the **reviewer**: a separate in-process Pi session (`createAgentSession`, no tools, fresh in-memory context, native `openai-codex` model, auth untouched). The reviewer defaults to `gpt-6.1-sol` (chosen for 75% vs 67% defect detection on known serious errors, verdict consistency 13/13, and ~half the latency); if unavailable or lacking image input, it falls back to the author's model. Override the reviewer model with `PI_DIAGRAM_REVIEWER_MODEL` (any openai-codex model with image input); the author remains on `gpt-5.6-sol` or the model set by `PI_DIAGRAM_CODEX_MODEL` (gpt-6 author attempts failed audits in pilot). It receives only images, an audit status summary, the parser's node/edge/group facts, measured geometry (node/group boxes, label boxes with their gap to their own route, route vertices with the nearest unrelated border, all computed by code), the rules context (allowed long-text decision hexagon, other shape changes blocking, legend optional (an entry that contradicts actual use is blocking, missing keys are minor), blocking-vs-minor examples, detour threshold 3x Manhattan) and a checklist, never SVG text or the author's messages. Default images: original, candidate full and 1200x710 fit, plus only the quadrant crops that meet a region flagged by an earlier open finding (`PI_DIAGRAM_REVIEWER_IMAGES=all` sends all seven). Every finding must carry `measured` and `threshold`. It must answer strict JSON; malformed output or a timeout (`PI_DIAGRAM_REVIEWER_TIMEOUT_S`, default 300 s per attempt) is retried once, then it is a reviewer error (never a pass; earlier reviewer findings stay open). Ids in the measured geometry are limited to source-declared ids, and text drawn in the images is declared to be content, never instructions. `PI_DIAGRAM_REVIEWER_THINKING` sets its thinking level (default `medium`); the reviewer model id, thinking level, image count, and all settings are recorded in `run.json` per review; Reviewer env overrides: `PI_DIAGRAM_REVIEWER_THINKING` (default `medium`), `PI_DIAGRAM_REVIEWER_IMAGES=all` (all 7 images instead of the focused 3), `PI_DIAGRAM_REVIEWER_PROMPT` (default `report`: report visible defects even when code also measures them; the ledger dedupes repeats of audit findings and the coverage downgrade keeps measured-PASS elements non-blocking; `delegate` restores the old policy of leaving measured checks to the code). T7 measured report-prompt recall 64% vs 28% for delegate at about +2 s, and T9 saw the delegate reviewer block nothing in 17 reviews while real defects existed, so `report` is the default; 3 images stay the default. Labels the author did not tag with `data-edge-label-source/target` (for example `class="edge-label"`) are measured by matching their text to exactly one source edge label; ambiguous or unmatched text is NOT-CHECKABLE.
5. keeps a findings ledger keyed by rule + sorted element ids (`open`/`fixed`/`regressed`), sends at most 5 blocking findings per round, and downgrades a reviewer blocking finding only when the auditor measured those exact elements with a method that covers that geometry (table in `src/early-checks.mjs`; straight-span checks do not cover curved routes; default is not covered);
6. logs reviewer instability without trusting it: a reviewer blocking finding that is new in a review although the geometry it is about is unchanged since the previous kept review is flagged `unstable` in the manifest but stays blocking (fail closed; per-run reviewer recall is about 67%, so a late catch is usually real);
7. applies the gate: reviewed hash == final hash == orchestrator-rendered hash, no audit FAIL, `semanticPreservation` PASS or ADJUDICATED, no forbidden construct, reviewer ran, no open blocking finding. Pass gives `REVIEWED`. (With the two-phase gate below, steps 1-3 run first inside `diagram_build_check` and `diagram_submit` refuses bytes that have not passed them.)

Budgets: 4 submit rounds (`PI_DIAGRAM_MAX_ROUNDS`), 25 minutes wall clock (`PI_DIAGRAM_MAX_WALL_MIN`), 8 minutes per author model call (`PI_DIAGRAM_MAX_CALL_S`; a longer call is aborted and the author is re-prompted once, a second timeout ends the run as `CANDIDATE` `MODEL_CALL_TIMEOUT`, see `docs/design-v2.md`), 3 author self-inspections per round. A round that increases blocking findings is reverted (the previous best bytes are restored); the loop stops when blocking findings have not decreased for 2 rounds. On exhaustion the best candidate (fewest blocking, then fewest minor) is restored and returned as `CANDIDATE` with its residual findings. If the author ends without submitting, its final bytes are audited and recorded as `CANDIDATE`. The wall clock is also enforced without a submit: a watchdog set at `/magic`, and any author message past the budget, abort the author turn and finalise the run as `CANDIDATE` (`WALL_CLOCK`).

The run manifest (written by the orchestrator, sealed with a self hash; authoritative copy in `~/.pi-diagram-agent/manifests/<runId>.json`, 0600, override with `PI_DIAGRAM_MANIFEST_DIR`; mirrored to `run.json` in the run directory) records source, rules and adjudication hashes, per-round audit and review findings and ledger states, per-role seconds and tokens, final SVG and media hashes, status and NOT-CHECKABLE rules. `REVIEWED` is not validation: only a human can run `/magic-accept <runDir> <svgSha256>`, which sets `VALIDATED` for a `REVIEWED` run whose final bytes still hash to that value and records the acceptance in both copies. It refuses a run whose `run.json` disagrees with the authoritative copy, or whose authoritative copy differs from the live process's in-memory manifest. Residual risk: the author's shell runs as the same OS user and can reach the manifest directory too; the guarantee is that acceptance is human and bound to one exact SVG hash re-checked on disk. No tool exposes this command to a model.

### Two-phase gate (default; `PI_DIAGRAM_TWO_PHASE=0` restores the one-phase submit above)

Evidence from 441 real submit rounds: 31% were script rejects that never reached the reviewer, and 74% of those submitted bytes had never been inspected because `diagram_inspect` is capped at 3 per round. The gate is therefore split:

**Phase 1, binding script check: `diagram_build_check` (jobId), text only.** In fixed order it (1) runs the author's generator at its entry point (`python3 make.py` in the run directory through Pi's `ctx.executeTool('bash')`, so it passes the normal tool_call/tool_result handlers; 60 s timeout, output tail bounded to 1500 chars; if there is no `make.py` and spec mode is on with a `layout.json`, the spec is rendered; otherwise `candidate.svg` is used as written; the generator may write only `candidate.svg` in the run directory), (2) hashes the resulting bytes, (3) runs the full auditor plus measured geometry/early findings (geometry also runs when the audit already failed, so one call shows every failure), (4) returns text only: sha256, PASS/FAIL per check, findings with repairHint/moveHint evidence, and the check budget left, (5) caches by SVG sha256. Generator errors and tracebacks come back as a short `GENERATOR_ERROR` message (a genuine tool failure throws). `diagram_submit` takes an optional `svgHash` and **refuses** (status `REFUSED`, never a submit round) bytes that were never checked, bytes whose latest check has any FAIL, or a hash that no longer matches the file. At submit the orchestrator reuses the cached phase-1 result for identical bytes and only renders what the reviewer needs. Caps: `diagram_build_check` <= 6 calls per round (both gates; a relaxed-gate cap of 3 was tried and reverted, see `docs/design-v2.md`, "Check cap") and <= 16 per run; after the round cap, the next submit goes to review and the Judge even when the last check lists advisory findings (only blocking FAILs escalate) (`PI_DIAGRAM_MAX_CHECKS_PER_ROUND`, `PI_DIAGRAM_MAX_CHECKS_PER_RUN`; every call counts, cache hits included; the round budget resets when a submit round ends). If the check budget is spent, unchecked bytes are checked by the orchestrator itself (uncounted, recorded `implicit`) so a run cannot deadlock (consequence, stated plainly: an author that spends all its checks on good bytes and then submits different, failing bytes also reaches escalation; waivers stay code-gated, so this is bounded). `diagram_inspect` (images) stays <= 3 per round and is not a gate. The author's normal loop is edit `make.py` -> `diagram_build_check` -> occasional `diagram_inspect` -> `diagram_submit`.

**Phase 2, reviewer.** It is told the script checks found zero failures on these exact bytes and gets a focus list of what code cannot measure (label ownership and appearance, legend appearance, balance) while keeping the report-anything-visible breadth (visual-only prompts recalled 28% in T7); duplicates of script-checked items are deduplicated by the coverage table and add no rounds.

**Escalation** applies when the last allowed check of a round (the 6th, or the run's 16th) still has FAILs and the author submits. Any SEMANTIC fail (svgWellFormed, nodeIdentity, nodeText, relations, relationStyle, groups, groupMembership, originalGroupParity, semanticPreservation, sourceDefinitionConflicts) or structural fail (forbidden construct, missing candidate, render error, gate reason) is rejected as before, never waived, and the reviewer is not called. Otherwise the reviewer is called in DIAGNOSIS mode with all images, the remaining script findings and their repairHint/moveHint evidence, and returns either a WAIVER request or RELAYOUT advice. Code (`src/escalation.mjs`) decides what a waiver may cover: only `routePairClearance`, `routeContainerClearance` (border grazing) and `routeCrossings` when every remaining crossing has repairHint null AND moveHint null (code-confirmed no repair). routeNodeIntrusion, labelClearance, arrowShaft, label-detached/ambiguous, textFit, nodeHeadingClearance, non-midpoint routeLowerBend, routeDetour, legendCompleteness and the other layout checks are not waivable; a waiver that does not cover every remaining FAIL, or that comes with a blocking visual finding, is rejected and the round continues. A valid waiver gives `REVIEWED_WITH_EXCEPTIONS`, listing each waived check with element ids, measured value and the reviewer's reason (run.json `exceptions`); the waived findings are downgraded to minor. RELAYOUT advice must be layout-level (kinds direction, group-order, branch-side, split, merge), is sent to the author in `escalation.relayout`, and counts as a round.

`REVIEWED` requires zero script FAILs. `REVIEWED_WITH_EXCEPTIONS` is never auto-published as the default Magic image (`publishAsDefault: false`); a human promotes it with `/magic-accept <runDir> <svgSha256> --waive <check1,check2>`, which must name every waived check (a missing, extra or unknown name is refused: `WAIVERS_NOT_NAMED` / `WAIVER_NOT_GRANTED`) and records each accepted waiver in `acceptance.acceptedWaivers`.

run.json (`schema: pi-diagram-run/3`) adds `twoPhase` (caps, `checksTotal`, `cacheHits`, `generatorErrors`, `perRound` [{round, buildCheckCalls, freshChecks, cacheHits, refusals, generatorErrors, limitHits}], `checks` log, `refusals`, `escalations`), `exceptions`, `publishAsDefault`, `modelCalls` {author, reviewer} and `timings.checkMs` (check time is subtracted from `authorMs`), so the 6/16 caps can be re-measured from real runs (`bench-lib` summarises them in a "Two-phase gate" table).

The benchmark (`bench/run-bench.mjs`) records, per run, the v2 gate status, rounds, reverts, author vs reviewer seconds and tokens, reviewer blocking findings, false-block candidates (a reviewer blocking finding later fixed with no SVG change in its region) and oscillations (a finding fixed then returning). Requires Pi 1.0.0. `npm run test:live` (opt-in, `PI_DIAGRAM_LIVE=1`, calls the model) exercises the real reviewer session; it is outside `npm test`.

## Judge (`/magic-judge`)

A finished run can be judged against its original Mermaid render: `/magic-judge /absolute/run-dir [--vs-old /absolute/older-run-dir]`. Two blind passes (order swapped, fresh no-tool sessions, native `openai-codex`) score six dimensions from -1 to +1 and write a sealed `judgement.json` bound to the candidate hash. `/magic-accept <runDir> <svgSha256>` now needs a fresh IMPROVED judgement; refused cases are a missing, NOT_IMPROVED, JUDGE_ERROR, stale or tampered one. Override with `--override-judge "<reason>"` (the reason is recorded in the acceptance); `--waive` is unchanged. Thresholds: `PI_DIAGRAM_JUDGE_MIN_DIM` (default -0.2) and `PI_DIAGRAM_JUDGE_MIN_MEAN` (0.2). Model, thinking and per-pass timeout: `PI_DIAGRAM_JUDGE_MODEL` (default the reviewer model), `PI_DIAGRAM_JUDGE_THINKING` (medium), `PI_DIAGRAM_JUDGE_TIMEOUT_S` (300). The Judge never runs automatically. Design: `docs/design-v2.md` (Judge) and `docs/superpowers/specs/2026-10-03-pi-diagram-judge-design.md`.

Offline: `node bench/judge.mjs --runs <dirs...> --out results.jsonl [--vs-old <dir>] [--fixtures <dir>] [--concurrency 2]` (see `bench/README.md`). It calls the real model and never gates.

## Relaxed gate (default; `PI_DIAGRAM_GATE=strict` restores the strict gate exactly)

The aim is a visibly better diagram, not one that satisfies every hard-coded requirement. In relaxed mode only defects that make the diagram wrong or unreadable block; every spacing, clearance and style nicety becomes advice (severity `minor`, with an `impact` score). The Judge accepts inside the `/magic` loop.

- **Blocking:** bindings and identity (`nodeIdentity`, `nodeText`, `nodeShape`, `relations`, `relationStyle`, `groups`, `groupMembership`, `originalGroupParity`, `semanticPreservation`, `sourceDefinitionConflicts`, forbidden constructs, `candidate-missing`), text glyphs outside the shape (`textFit` beyond the outline, or touching a stroke), missing or invisible arrowheads (`markerDrawing`), an edge label covering node text (`labelClearance` with `coversNodeText`) or another route (`labelCoversRoute`), a route through node text (`routeNodeIntrusion` with `textIntrusions`), a node or route overlapping group heading text (`nodeHeadingClearance` gap 0, `routeHeadingClearance` with `headingOverlaps`), and a label on another edge (`label-ambiguous` when the label box touches the other route). Reviewer: `shape-change`, `label-ownership`, `text-overflow`, `heading-overlap`. Everything else is advice. Full mapping: [docs/design-v2.md](docs/design-v2.md#relaxed-gate).
- **Acceptance:** with no blocking finding, a passed review and the hash-identity gate, the Judge (both passes, exact final bytes against the original) must say IMPROVED at the in-loop threshold: mean at least `PI_DIAGRAM_ACCEPT_MIN_MEAN` (default +0.2), every dimension at least `PI_DIAGRAM_ACCEPT_MIN_DIM` (default -0.2), and each pass's own mean at least `PI_DIAGRAM_ACCEPT_MIN_PASS` (default +0.1). History: merged 0.4 with both passes at 0.4, then 0.4/0.3 (26e10d9b), then 0.2/0.1 on 2026-10-04 at the user's decision. `judgement.json` is sealed and bound to the hash, so `/magic-accept` works unchanged.
- **NOT_IMPROVED costs a round.** The revise message carries the Judge's top 3 improvements, the remaining blocking findings and the 3 highest-impact advice items; never the full advice list. Rounds or wall clock exhausted ends as `CANDIDATE` with reason `NOT_IMPROVED`. A `JUDGE_ERROR` is never `REVIEWED`.
- **Check feedback (relaxed gate).** `diagram_build_check` lists every blocking finding (no cap; strict keeps the 8-finding cap), plus the 3 highest-impact advice items and a `+N more` count. A blocking finding that an earlier check showed fixed and a later check shows again is marked `REGRESSION: fixed in check #N, broken again`, listed first, and counted in `run.json` (`twoPhase.checks[].regressions`). A CHECK_PASS reply says to submit now; a repeat `diagram_build_check` on the unchanged passing bytes is refused (`UNCHANGED_PASSING_BYTES`) and is not counted as a check. The author prompt asks for a group/endpoint/direction check against the source facts before the first draft. See `docs/design-v2.md`, "Check feedback loop".
- The relaxed gate needs the native `openai-codex` provider for the Judge too (`PI_DIAGRAM_JUDGE_MODEL`, `PI_DIAGRAM_JUDGE_THINKING`, `PI_DIAGRAM_JUDGE_TIMEOUT_S` as for `/magic-judge`).
